## 1. Методология BEM

**BEM** (Block Element Modifier) — методология именования классов, помогающая писать предсказуемый и переиспользуемый CSS.

### 1.1. Три понятия

1. **Блок (Block)** — независимая сущность: `header`, `card`, `button`, `menu`.
2. **Элемент (Element)** — часть блока, не существует отдельно: `card__title`, `menu__item`.
3. **Модификатор (Modifier)** — состояние/вариант: `button--primary`, `button--disabled`.

### 1.2. Правила именования

```
блок
блок__элемент    (двойное подчёркивание __)
блок--модификатор (двойной дефис --)
блок__элемент--модификатор
```

Примеры:
- `card`
- `card__title`
- `card__button`
- `card--featured`

HTML:

```html
<div class="card card--featured">
    <h2 class="card__title">Заголовок</h2>
    <p class="card__text">Текст</p>
    <button class="card__button">Подробнее</button>
</div>
```

CSS:

```css
.card { border: 1px solid #ddd; border-radius: 8px; padding: 20px; }
.card--featured { border-color: #f39c12; }
.card__title { font-size: 1.4rem; margin: 0 0 8px; }
.card__text { color: #555; }
.card__button { background: #3498db; color: #fff; border: none; padding: 8px 16px; }
```

### 1.3. Почему BEM полезен

- **Предсказуемость:** по классу сразу понятна структура.
- **Без конфликтов:** специфичность низкая и одинаковая (все селекторы одной силы).
- **Переиспользование:** блоки можно копировать между проектами.
- **Масштабируемость:** легко поддерживать большой проект.

### 1.4. Что можно (правила-нюансы)

- Элемент вкладывается **внутри своего блока** в дереве (но имя класс всегда `блок__элемент`, без вложенности в имени).
- **Модификатор** добавляется вместе с базовым классом: `class="card card--featured"`.
- Блок может содержать другие блоки (вложенность блоков допустима).
- Не делайте длинные цепочки `block__elem__sub--mod` — это признак ошибки.

### 1.5. Частые ошибки

| Ошибка | Как правильно |
|--------|---------------|
| `block__elem__sub` — тройная вложенность | Делайте отдельный блок или упростите |
| Модификатор вместо элемента в имени | `card--title` неверно; нужно `card__title` |
| Стилизация по селектору типа (`div p`) внутри BEM | Используйте классы |
| Класс-модификатор без базового класса | `card--featured` один — без `card` не сработает базовый стиль |
| Крупная вложенность селекторов | BEM «плоский»: один класс = одно правило |

## 2. Организация CSS и препроцессоры

### 2.1. Структура файлов

Разделяйте стили по смыслу:

```
css/
├── base/          /* сброс, переменные, типографика */
│   ├── reset.css
│   └── variables.css
├── components/    /* кнопки, карточки (BEM-блоки) */
│   ├── button.css
│   └── card.css
├── layout/        /* сетка, header, footer */
├── pages/         /* стили конкретных страниц */
└── main.css       /* главный файл: @import всего */
```

### 2.2. Принципы организации

- **Reset/Normalize** — единая база стилей: `margin:0`, `box-sizing` и т.д.
- **Переменные** — цвета, отступы, радиусы в одном месте.
- **Порядок в каскаде** — следите за специфичностью и порядком подключения.
- **Комментирование секций** и стилевой гайд команды.

```css
/* ---------- Reset ---------- */
*, *::before, *::after { box-sizing: border-box; }
body, h1, h2, h3, p { margin: 0; }
img { max-width: 100%; display: block; }

/* ---------- Variables ---------- */
:root { --main: #3498db; --radius: 8px; }
```

### 2.3. Введение в Sass/SCSS

Препроцессор — надстройка, добавляющая переменные, вложенность, миксины, которые затем компилируются в обычный CSS.

**Переменные:**

```scss
$main: #3498db;
$radius: 8px;

.btn { background: $main; border-radius: $radius; }
```

**Вложенность (упрощает BEM):**

```scss
.card {
    border: 1px solid #ddd;
    &__title { font-weight: bold; }
    &--featured { border-color: $main; }
}
```

**Миксины (переиспользуемые куски):**

```scss
@mixin flex-center {
    display: flex;
    align-items: center;
    justify-content: center;
}

.box { @include flex-center; }
```

**Наследование через `@extend`** и логика через `@if`/`each`.

> Запуск: Sass-файлы компилируются в CSS (инструмент `sass`, сборщик, VS Code-расширение). Браузер сам Sass **не понимает**.

### 2.4. PostCSS

PostCSS — инструмент трансформации CSS через плагины: автопрефиксы (добавление `-webkit-` и др.), минификация, поддержка современных свойств. Встраивается в сборку (Vite, webpack).

### 2.5. Тёмная/светлая тема и дизайн-токены

Дизайн-токены (переменные) — единый источник цвета/типографики:

```css
:root {
    --color-bg: #fff;
    --color-text: #222;
    --color-primary: #3498db;
    --space-1: 4px;
    --space-2: 8px;
}
@media (prefers-color-scheme: dark) {
    :root { --color-bg: #111; --color-text: #eee; }
}
body { background: var(--color-bg); color: var(--color-text); }
```

## 3. Инструменты разработки

### 3.1. Live Server (VS Code)

Расширение **Live Server** запускает локальный сервер с автоперезагрузкой страницы при сохранении — мгновенный отклик на изменения.

### 3.2. @import и сборка

- `@import` в CSS объединяет несколько файлов (но каждое подключение — отдельный запрос; в проде лучше собирать в один файл).
- Современные сборщики (Vite, webpack) **конкатенируют** и **минифицируют** CSS автоматически.

```css
/* main.css */
@import "base/reset.css";
@import "components/button.css";
@import "components/card.css";
```

> ⚠️ `@import` должен идти в **начале** CSS-файла, иначе игнорируется частью браузеров. Для продакшена предпочтительна сборка в единый файл.

### 3.3. Минификация

Убирает пробелы/комментарии, сокращает имена. Файл меньше — страница грузится быстрее. Выполняется сборщиком/плагинами при деплое.

### 3.4. DevTools — ключевой инструмент

Полезные приёмы:
- **Elements → Styles** — живое редактирование стилей, проверка применённых правил и специфичности.
- **Computed** — итоговые (вычисленные) значения свойств.
- **Device Toolbar** — проверка адаптивности на разных ширинках.
- **Screenshot / измерения** — проверка размеров.
- **Performance** — анализ «дорогих» анимаций.

### 3.5. Проверка доступности и валидности

- Валидатор HTML (validator.w3.org).
- Расширение **axe DevTools** / Lighthouse (встроен в Chrome) — аудит доступности и производительности.

## Упражнения

### BEM
1. Перепишите карточку из [Раздела 1](grid.md) в BEM-именовании.

4. Разбейте стили своего проекта на файлы (variables, base, components).
5. Познакомьтесь с Sass: настройте компиляцию и напишите пару миксинов.
6. Вынесите цвета/отступы в дизайн-токены.

7. Установите Live Server и пользуйтесь автоперезагрузкой.
8. Соберите несколько CSS-файлов в один через импорт/сборщик.
9. Прогоните страницу через Lighthouse, исправьте найденные проблемы доступности.
