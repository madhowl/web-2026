## 1. Адаптивность и отзывчивость

### 1.1. Адаптивный vs отзывчивый

- **Адаптивная вёрстка** — набор «макетов» для определённых ширин (брейкпоинтов).
- **Отзывчивая (responsive)** — плавно «течёт» при любой ширине (проценты, fr, clamp).

Современный подход сочетает оба: **отзывчивые** сетки + **адаптивные** перестройки на брейкпоинтах.

### 1.2. Мобильный-first подход

Сначала верстаем под **мобильный** (базовые стили), затем через `@media (min-width: ...)` постепенно расширяем под больше экраны.

Преимущества:
- Проще: базовый код лечит самую «сложную» (узкую) версию.
- Естественно «растёт» от простого к сложному.

```css
/* Базовые (мобильные) стили */
.cards { display: grid; gap: 10px; }

/* Планшет */
@media (min-width: 768px) {
    .cards { grid-template-columns: repeat(2, 1fr); gap: 20px; }
}

/* Десктоп */
@media (min-width: 1024px) {
    .cards { grid-template-columns: repeat(3, 1fr); }
}
```

### 1.3. Логические операторы в медиа-запросах

- `and` — оба условия истинны.
- `,` (запятая) — логическое ИЛИ.
- `not` — отрицание.

```css
/* Широкий планшет или десктоп */
@media (min-width: 768px) and (max-width: 1024px) { ... }

/* Тёмная тема и узкий экран */
@media (max-width: 600px) and (prefers-color-scheme: dark) { ... }
```

Современный синтаксис диапазонов (без `min-`/`max-`, поддерживается в новых браузерах):

```css
@media (width >= 768px) { ... }        /* эквивалент min-width: 768px */
@media (width <= 600px) { ... }
```

### 1.4. Fluid-типографика и единицы

**Текст:** `clamp()` для «резинового» размера:

```css
body { font-size: clamp(16px, 1.2vw + 12px, 20px); }
```

> Есть техника **Fluid Type Scale**: задать функцию через CSS-переменные, чтобы вся шкала масштабировалась.

**Сетки:** доли `fr`, проценты, `auto-fit`.

**Контейнеры:**

```css
.container {
    width: 100%;
    max-width: 1200px;
    margin: 0 auto;
    padding-inline: 16px;
}
```

### 1.5. Гибкие изображения

```css
img,
video {
    max-width: 100%;
    height: auto;
}
```

**srcset** — браузер сам выбирает лучшее изображение по ширине экрана:

```html
<img src="pic-800.jpg"
     srcset="pic-400.jpg 400w, pic-800.jpg 800w, pic-1200.jpg 1200w"
     sizes="(max-width: 600px) 100vw, 50vw"
     alt="Описание">
```

- `400w` и т.д. — фактическая ширина изображения.
- `sizes` — сколько места займёт картинка.

**`<picture>`** — для замены на разные форматы/кадрирования:

```html
<picture>
    <source media="(min-width: 800px)" srcset="wide.jpg">
    <source media="(max-width: 799px)" srcset="square.jpg">
    <img src="fallback.jpg" alt="Описание">
</picture>
```

**Пропорции через `aspect-ratio`:**

```css
.media {
    aspect-ratio: 16 / 9;  /* зарезервировать место, избежать «прыжка» при загрузке */
    object-fit: cover;     /* обрезать без искажений */
    width: 100%;
}
```

### 1.6. Брейкпоинты: как выбирать

Не привязывайтесь жёстко к конкретным устройствам. Используйте брейкпоинты по **содержимому**: где макет «ломается», там и ставьте запрос.

Распространённые ориентиры (mobile-first `min-width`):
- 576px — крупные телефоны/лёгкий планшет
- 768px — планшеты
- 992px — ноутбуки
- 1200px — десктоп

> 💡 Лучший инструмент проверки — **DevTools** браузера: переключайте ширину экрана и находите точки, где сетка ломается.

## 2. Доступность (a11y)

Доступность — чтобы сайтом могли пользоваться **все**, включая людей с ограничениями (нарушения зрения, моторики) и пользователей с клавиатуры/скринридеров.

### 2.1. Семантика — фундамент a11y

Используйте правильные теги: `<header>`, `<nav>`, `<main>`, `<article>`, `<footer>`, `<button>` для кнопок, `<label>` для полей. Это бесплатная доступность «из коробки».

- Кнопка — `<button>`, а не `<div onclick>` (недоступно для скринридеров и клавиатуры).
- Поля всегда с `<label>` и правильным `type`.

```html
<label for="email">Email:</label>
<input type="email" id="email" name="email" required>
```

### 2.2. ARIA-атрибуты (дополнение к семантике)

ARIA помогает описать элементы, когда нативной семантики не хватает. Используйте **умеренно** — лишний ARIA хуже его отсутствия.

```html
<!-- роль диалога -->
<div role="dialog" aria-labelledby="title" aria-modal="true">
    <h2 id="title">Модальное окно</h2>
    <button aria-label="Закрыть">×</button>
</div>
```

Частые атрибуты:
- `aria-label` — доступное имя (для иконок-кнопок).
- `aria-labelledby` — связь с текстом.
- `aria-hidden="true"` — скрыть от скринридера (декоративные элементы).
- `aria-expanded` — состояние сворачивания (для аккордеонов).
- `role` — роль: `dialog`, `navigation`, `alert`, `status` и др.

> **Правило:** если есть нативный элемент (button, nav, input) — используйте его вместо `role`.

### 2.3. Навигация с клавиатуры и focus

- Все интерактивные элементы должны быть **достижимы** через `Tab` и иметь **видимый фокус**.
- Не стирайте `:focus` совсем — заменяйте на собственный стиль.

```css
:focus-visible {
    outline: 3px solid #3498db;
    outline-offset: 2px;
}
```

- **Skip-link** («ссылка-обманка» для перехода к контенту, минуя меню):

```html
<a class="skip-link" href="#main">Перейти к содержанию</a>
```

```css
.skip-link {
    position: absolute;
    left: -9999px;
}
.skip-link:focus {
    left: 16px;
    top: 16px;
    position: fixed;
    background: #fff;
    padding: 8px 16px;
    z-index: 100;
}
```

### 2.4. Контраст цветов

Текст должен контрастировать с фоном (WCAG AA: минимум **4.5:1** для обычного текста, **3:1** — для крупного). Плохой контраст — самая частая проблема.

Проверяйте контраст в DevTools (инструмент «axe» или встроенный) или на онлайн-проверках.

```css
/* Плохо: серый на сером */
.low { color: #9a9a9a; background: #d0d0d0; }
/* Хорошо: тёмный на светлом */
.good { color: #222; background: #fff; }
```

### 2.5. Текст и изображения

- Все `img` с осмысленным `alt` (или `alt=""` для декоративных).
- Не передавайте смысл только цветом (добавляйте значки/текст).
- Не полагайтесь на `title` как на alt.

### 2.6. prefers-reduced-motion

Уважайте пользователей, отключивших анимации (см. [Раздел 5-6](animation.md#27-prefers-reduced-motion-доступность)).

## Разбор типичных ошибок

| Ошибка | Исправление |
|--------|-------------|
| Забыт `<meta name="viewport">` | Мобильная вёрстка не работает без него |
| Кнопка-`div` вместо `<button>` | Недоступна; используйте `<button>` |
| `outline: none` без замены | Замените на `:focus-visible` стиль |
| Плохой контраст текста | Поднимайте контраст ≥ 4.5:1 |
| Картинки без `alt` | Добавьте описание (`alt=""` для декоратива) |
| `srcset`/`sizes` забыли | Мобильные грузят тяжёлые изображения — используйте srcset |
| Анимация без `prefers-reduced-motion` | Отключите/упростите для тех, кто просит |
| ARIA-лишнее | Насколько можно — нативная семантика |

### Дополнительно
- Используйте `html`/`body` с осмысленным `lang="ru"`.
- Заголовки должны идти по порядку (не пропускать уровни).
- Формы валидируйте и показывайте понятные сообщения об ошибках.

## Упражнения

### Адаптивность
1. Возьмите каркас из [Раздела 1](grid.md#9-практика-каркас-сайта) и адаптируйте: на мобильном сайдбар уходит вниз.
2. Сделайте font-size через `clamp()`.
3. Добавьте `aspect-ratio: 16/9` и `object-fit: cover` для изображений.
4. Проверьте верстку в DevTools на разных ширинках (375, 768, 1024, 1440).

### Доступность
5. Добавьте skip-link на страницу.
6. Замените все `<div>`-кнопки на `<button>` и добавьте `:focus-visible`.
7. Проверьте контраст текста и исправьте низкий.
8. Добавьте `@media (prefers-reduced-motion: reduce)`.
